# MTAG | منظومة الطيران العالمي

نظام إدارة تراخيص طيران متكامل لمنظمة MTAG الخيالية التابعة لروبلكس.

> ⚠️ **منظمة خيالية تابعة لروبلكس لا تمثل الواقع ولا تمت له بصلة.**
> هذا المشروع مخصص حصراً لبيئة لعب أدوار (roleplay) ترفيهية على روبلكس، ولا يمثل
> أي جهة طيران، حكومة، جيش، شركة طيران، أو منظمة دولية حقيقية.

يعمل المشروع بالكامل محلياً على جهازك (localhost) — لا حاجة لاستضافة سحابية،
لا دومين، لا رسوم اشتراك. مبني بـ Node.js ويستخدم قاعدة بيانات SQLite مدمجة
(`node:sqlite`) بدون أي اعتمادية أصلية (native) تحتاج تصريف — لذلك التثبيت بسيط
وسريع على أي جهاز.

---

## المتطلبات

- Node.js **v22.5 أو أحدث** (تم تجهيزه واختباره خصيصاً لـ **v24.18.0** كما طلبت).
- لا حاجة لأي برنامج آخر (لا MySQL، لا Postgres، لا Docker).

---

## 1) تثبيت الاعتماديات (Dependencies)

افتح الطرفية (Terminal) داخل مجلد المشروع ثم نفّذ:

```bash
npm install
```

---

## 2) ضبط متغير Discord Webhook وباقي الإعدادات

انسخ ملف `.env.example` وأعد تسميته إلى `.env`:

```bash
cp .env.example .env
```

(على ويندوز استخدم: `copy .env.example .env`)

ثم افتح `.env` وتأكد من القيم التالية:

```env
PORT=3000
SESSION_SECRET=ضع_هنا_نص_عشوائي_طويل
DISCORD_LICENSE_WEBHOOK_URL=https://discord.com/api/webhooks/xxxxx/xxxxx
```

- **SESSION_SECRET**: نص عشوائي طويل يُستخدم لتوقيع جلسات الموظفين. يمكنك توليد
  واحد بسرعة عبر:
  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```
  انسخ الناتج وضعه بدل القيمة الافتراضية.

- **DISCORD_LICENSE_WEBHOOK_URL**: رابط الـ Webhook الخاص بقناة سجل التراخيص في
  Discord (تم وضع الرابط الذي زوّدتني به مسبقاً في `.env.example`). هذا المتغير
  يُستخدم من طرف الخادم (backend) فقط، ولا يظهر أبداً في المتصفح أو كود الواجهة.

⚠️ ملف `.env` نفسه مستثنى من Git (`.gitignore`) حتى لا يُنشر رابط الـ Webhook
بالخطأ إذا رفعت المشروع لاحقاً على GitHub.

## 3) قاعدة البيانات المحلية

لا حاجة لأي إعداد يدوي — عند أول تشغيل للخادم، سيُنشئ تلقائياً:

- مجلد `data/` في جذر المشروع
- ملف قاعدة بيانات `data/mtag.db` (SQLite)
- كل الجداول اللازمة (الموظفون، التراخيص، سجل التدقيق، الجلسات)

افتح المتصفح على:

## 6) إنشاء أول حساب مدير (Administrator)

في طرفية جديدة (اترك الخادم يعمل)، نفّذ:

```bash
npm run create-admin
```

سيسألك السكربت بالترتيب عن:

1. اسم المستخدم (أحرف إنجليزية/أرقام فقط)
2. الاسم الكامل
3. الدور الوظيفي (اكتب `Administrator` أو اتركه فارغاً لأنه الافتراضي)
4. كلمة المرور (8 أحرف على الأقل) — يتم إخفاؤها أثناء الكتابة
5. تأكيد كلمة المرور

بعد النجاح، سجّل الدخول عبر: `http://localhost:3000/employees/login`

يمكنك تكرار هذا الأمر لاحقاً لإنشاء موظفين إضافيين بأدوار مختلفة (License
Officer / Reviewer / Viewer)، أو استخدام صفحة "إدارة الموظفين" داخل لوحة تحكم
المدير لإضافتهم مباشرة من الواجهة.

---

## 7) إنشاء أول ترخيص

1. سجّل الدخول كمدير.
2. من لوحة التحكم اضغط **"+ ترخيص جديد"**.
3. عبّئ البيانات (اسم الحامل، نوع الترخيص، الفئة، تاريخ الإصدار/الانتهاء، صادر عن...).
4. اضغط **"إصدار الترخيص"**.

سيتولى النظام تلقائياً:
- توليد رقم ترخيص فريد بصيغة `077.XXXXXX.MTAG`
- حفظ الترخيص في قاعدة البيانات المحلية
- إرسال إشعار Discord Embed لقناة سجل التراخيص
- تسجيل العملية في سجل التدقيق

---

## 8) اختبار إشعار Discord

بعد إنشاء أول ترخيص (الخطوة السابقة)، تحقق من قناة الـ Discord المرتبطة
بالـ Webhook — يجب أن تصلك رسالة Embed بعنوان **"🛫 MTAG | ترخيص جديد"** تحتوي
على كل تفاصيل الترخيص.

إن لم تصل الرسالة:
- تأكد أن رابط `DISCORD_LICENSE_WEBHOOK_URL` في `.env` صحيح وفعّال (لم يُحذف
  الـ Webhook من إعدادات القناة في Discord).
- تحقق من سجل الطرفية التي يعمل بها الخادم — أي خطأ في الإرسال يُسجَّل هناك
  بوضوح، ولن يتكرر إنشاء الترخيص أو يتكرر السجل في قاعدة البيانات مهما حدث.

## بنية المشروع (ملخص)

```
mtag/
├── server.js                 # نقطة تشغيل الخادم
├── db/database.js            # تهيئة قاعدة بيانات SQLite والجداول
├── db/session-store.js       # مخزن جلسات مبني على SQLite
├── middleware/auth.js        # الحماية والصلاحيات (RBAC)
├── routes/                   # مسارات: تسجيل الدخول، التراخيص، التحقق، الإدارة
├── utils/                    # توليد رقم الترخيص، سجل التدقيق، Discord، التحقق
├── views/                    # صفحات EJS (عربي RTL)
├── public/                   # CSS و JS الخاص بالواجهة
├── scripts/create-admin.js   # سكربت إنشاء أول مدير
└── data/mtag.db              # قاعدة البيانات المحلية (تُنشأ تلقائياً)
```

## ملاحظات أمنية

- كلمات المرور مخزّنة بتشفير `bcrypt` (لا تُحفظ أبداً كنص صريح).
- كل الإدخالات تُتحقق منها على الخادم (server-side)، لا يُعتمد على الواجهة أبداً.
- أرقام التراخيص لا يمكن أن تتكرر — يُتحقق منها في قاعدة البيانات قبل الحفظ،
  إضافة إلى قيد `UNIQUE` على مستوى قاعدة البيانات نفسها كخط دفاع ثانٍ.
- رابط Discord Webhook لا يُخزَّن ولا يُستخدم إلا من طرف الخادم (server-side)،
  ولا يظهر أبداً في كود الواجهة أو أدوات المطوّر بالمتصفح.
- صفحات الإدارة محمية بالكامل، ولا يمكن للزوار العاديين الوصول إليها.
